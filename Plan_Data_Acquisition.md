
### План реализации: Модуль «Data Acquisition» (Сборщик каталога)


### 1. Слой данных и миграции (Persistence Layer)
**Цель:** Перестроить БД для поддержки гибкой структуры категорий и устранения дублей.

*   **Рефакторинг `src/db/models/models.py`:**
    - Создание таблицы ассоциации `album_category_association`.
    - Удаление `category_id` из `Album` (теперь связь через таблицу выше).
    - Добавление поля `cover_url` в `Album` (для отображения превью без захода внутрь альбома).
*   **Alembic Migration:**
    - Генерация миграции: `alembic revision --autogenerate -m "Refactor to many-to-many categories"`.
    - Применение: `alembic upgrade head`.
*   **Зачем:** Один альбом на Yupoo может физически находиться в разных папках. Мы сохраняем его один раз, но «вешаем» на него все подходящие ярлыки-категории.

---

### 2. Ядро автоматизации и очистки (Core Engine)
**Цель:** Обеспечить «невидимость» парсера и чистоту данных на входе.

*   **Модуль очистки (`src/core/security.py`):**
    - Реализация `clean_album_title`: Regex-паттерны для удаления цен (`¥`, `yuan`), WeChat/WhatsApp ID и лишних дат.
*   **Сервис Playwright (`src/services/playwright_service.py`):**
    - Singleton-класс для управления браузером.
    - Внедрение `playwright-stealth`.
    - **Senior Logic:** Принудительная установка заголовка `Referer: https://3125tiger.x.yupoo.com/` для каждого запроса (обход ошибки 567).
*   **Зачем:** Без чистых заголовков поиск по сайту превратится в мусор, а без обхода защиты Yupoo забанит IP через 5 минут.

---

### 3. Модуль «Разведчик» (Category Explorer)
**Цель:** Полностью скопировать дерево категорий поставщика.

*   **Реализация `src/modules/crawler/categories.py`:**
    - Скрипт заходит на страницу `/categories`.
    - Парсит боковое меню (Accordion) и выпадающий список в шапке.
    - **Recursive Logic:** Если у категории есть вложенные подкатегории, сохраняем их с указанием `parent_id`.
*   **Зачем:** Это база для навигации на твоем будущем сайте. Без этого этапа 30 000 товаров будут лежать «одной кучей».

---

### 4. Модуль «Сборщик» (Album Populator)
**Цель:** Массовое наполнение базы метаданными альбомов.

*   **Логика обхода (`src/modules/crawler/albums.py`):**
    - Загружает из БД список всех «листовых» категорий (те, у которых нет вложенных подкатегорий).
    - Для каждой категории перебирает страницы: `.../categories/ID?page=1, 2, 3...`.
    - На каждой странице парсит сетку из 120 альбомов.
*   **Логика сохранения (Upsert):**
    - Сохраняет альбом в БД. Если альбом с таким `yupoo_url` уже есть — обновляет заголовок и обложку, но не создает дубль.
    - Добавляет запись в таблицу ассоциаций (связывает текущий альбом с текущей категорией).
*   **Зачем:** Это самый долгий этап. На выходе мы получаем заполненную очередь задач для будущего Воркера (который будет лить фото в ТГ).

---

### Подводные камни (Senior Notes для Trae)

1.  **Duplicate Handling:** При парсинге глобального списка и отдельных категорий один и тот же альбом попадется нам многократно. Trae должен использовать `on_conflict_do_nothing` в SQLAlchemy, чтобы база не «кричала» об ошибках уникальности.
2.  **Rate Limiting:** Yupoo чувствителен к частоте запросов. Нужно использовать адаптивные задержки: `await asyncio.sleep(random.uniform(1.5, 4.0))`.
3.  **Missing Categories:** Некоторые альбомы на Yupoo не привязаны ни к одной категории. Нужно добавить логику проверки: «Если альбом найден в общем списке, но его нет в таблице связей — пометить его в категорию 'Other'».
4.  **Async Concurrency:** Не стоит запускать 100 потоков Playwright одновременно — это верный путь к бану. Оптимально: 1-3 параллельных контекста.
